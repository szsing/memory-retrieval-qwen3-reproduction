# Qwen3-8B 开发实验第一轮

仅 InMind 学习域 stream+gate 中按原始 ID 哈希固定选择的 20 条请求及其直接提问，共 40 条。没有访问 testA/testB 查询，不是保留测试结果。模型 BF16、non-thinking，BGE-small，top-6。

候选池协议：dense365 包含背景与全部事实；official241 在排序、RRF、候选生成和 picker 调用前限制为背景加本题事实。RRF 权重固定 2、常数 60；属性方法保留基础检索 top-1。picker 最多选 6 条，未选满时使用各方法自己的基础排序回填。所有 pick 对照使用相同 gate；recall 类型保留 dense。HyDE 实现为原仓库 Store.scores 的原请求与假想记忆混合，不等同于所有文献中的 HyDE 实现。

属性与查询生成采用批量 8，字段/ID 覆盖错误时拆批重试；单条仍错误则中止。原文最多按既有代码取 600 字符，picker 候选按既有代码取 300 字符。模型输出缓存独立保存在本目录。

初步判断：属性匹配在官方池有开发集信号；混合记忆场景增益较小；picker 没有稳定收益。仅 20 条开发请求，不能据此主张泛化或达到投稿标准。下一轮应先分析开发集候选覆盖、属性歧义和重排丢失，再冻结版本进行跨数据集检查。

方法成本不能从最终共享调用计数直接比较：生成结果跨方法复用，另应拆分写入成本和查询成本。环境联网探测曾超时，正式计算以离线缓存模式完成；重启复用相同模型缓存，未按结果改选样本或调参数。
