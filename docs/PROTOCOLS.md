# 协议与可比边界

## 主核验

模型：Qwen3-8B，权重revision `b968826d9c46dd6066d109eabc6255188de91218`，BF16，单张RTX4090，vLLM0.11。本地服务别名为`qwen3-8b-b968826-bf16-nothink-vllm011`。temperature=0，thinking禁用，回答上限2048 tokens。检索嵌入为BGE-small-en-v1.5；各系统原生查询预处理仍有差异。

InMind共125道间接题，先61道未见域，再64道开发域相关题。每题输入为同一240条背景加这一题目标事实，不写入其他124题事实。此241池是候选检索诊断，**不是官方47会话的完整时间线**。

原批量查询特征固定：HyDE15题/批、查询属性8题/批、gate20题/批。特征构建当时复用了32个已验证缓存响应，新增生成调用为0。写侧每池按30条/批，末批1条，未把其他任务事实放进该池写侧。

完整方法保留v2属性、属性权重8、HyDE、gate、wide候选与picker。`write_only_attr`不是移除所有读侧推理：它将抽象查询属性替换为原请求文本，仍与写侧属性匹配，也保留HyDE/gate/picker。`fact_presence`改为是否有属性的非语义信号并用固定HyDE分数破并列，其他组件保留。`rerank`为当前源码中的nojoin重排对照，包含原有回退逻辑，不能称作严格完全无属性的消融，也不是独立复现RankGPT。

统一读取端按顺序放入完整原生记忆单元，总上限4096 tokens；A-Mem保留原生链接扩展，RootMem保留结构化技能字段。原始文本方法仍检索6条。它不是要求不同记忆表示的字符数、信息量和写入token成本完全相同。

Mem0/A-Mem/RootMem与原始文本方法共用回答提示和本地模型；RootMem构建响应上限16384，其他常规调用2048。RootMem对外部RAG部分采用同一个BGE模型，是明确的适配，不能写成原论文配置原样复现。

## 记忆复用检查

InMind240条背景前缀先冻结，再克隆并追加每题事实。三套系统各用首题检查了“从零构建241条”与“240前缀＋追加事实”的状态等价性，检查排除了不影响内容的UUID/墙钟字段。后续查询前后检查记忆状态不变。首题检查通过不等于逐题人工验证语义提取一定正确。

原生输出引用有显式来源：Root4096、无记忆、oracle和原生三个系统的某些旧答案通过已记录的引用复用，**不是独立重跑的额外样本**。原始截断答案、共享365池、单题查询生成与冻结查询版本分别保留，不只保留有利版本。

## 两种主判分

`answer`使用InMind的`judge_answer_only.txt`，按其金标准解释要求检查个性化后果；`grounded`使用`judge_application.txt`，还检查检索上下文含有对应个人事实。两者的后端是本地Qwen，不是官方榜单指定后端。无记忆/正确事实oracle用作诊断。两套提示的局部判分有不一致，记录在审计文件中，尚需独立人工复核。

此前简化JUDGE会给一般性谨慎回答较高分，故保留作历史诊断，不作为主结论。8题×3条件的校准是AI助手盲审，**不是真人标注**，不能据此估算整体人工准确率。

## ImplexConv与LUCid补充设置

ImplexConv为原脚本test子集81题、30个候选池，每池149–233条。Mem0/A-Mem未完成81题；前20题只用于同题诊断。选择的是固定顺序的完整10题判分块，前10题和前20题两版都保留。

LUCid由原脚本固定哈希划分取240题。每题为自身latent会话用户发言，随后追加来自其他用户的100个无关会话，共有543条公共后缀；每池546–581条、240个不同池。**不是官方S（约1936题、50会话）的全量设置。** 原生系统在本扁平适配中按同一subject写入池内内容，因此并不是各系统的原生多用户隔离评测；跨用户干扰可能影响冲突更新。

公共部分是后缀，不能未经等价证明改成前缀来克隆。不同池的增量记忆状态不能偷换。现有缓存只复用请求完全相同且验证通过的响应。此构造任务的总写入时间也不应直接当作官方多用户记忆系统的效率排名。
